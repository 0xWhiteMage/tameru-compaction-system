## Deviations from the brief

- `presets.json` is read with `pathlib.Path.read_text`, not `importlib.resources`: `scripts/check_host_rules.py` flags any
  `importlib` import as dynamic code and the baseline may not grow.
- `decide(result, policy, *, original=None, fingerprints=None, sanitized=False, tokens_saved=None)`: the result does not hold
  the original text, so fingerprints and the character-based savings check need it passed in. A policy that requires
  fingerprints and gets neither input declines (`lost_fingerprint`, basis `original_missing`).
- Kind-aware markers opt in by declaring a parameter named `kind` (passed by keyword). `lambda *a` and 3-positional-parameter
  callables that do not name it are still called with two arguments, so no existing marker changes behaviour.
- DSH "too few tokens saved" is the host's own meter; `decide(..., tokens_saved=)` takes it, and falls back to the engine's count.
- `decide` filters the OUTPUT's trust-risk lines before comparing fingerprints (gate 11); the original side is unfiltered, as in 1.9.x.

## Early exit: NOT shipped

Brief item 8 asked for moving the empty/filler query guard (`_apply_query_guards`) ahead of scoring only if every field is
provably equal. It is not provable here: the guard only flips `fail_open`/`risk` on a result already built from scoring, and
the receipt, `kept_tokens`, `confidence`, `reasons` and `content_type` all derive from that scoring (and from the derive-query,
anchor-errors, prose-brief and adapter paths that run before the guard and can change the effective query). Moving it would
change those fields. The structural-pass-before-exit variant belongs to step 2 together with the golden regeneration.
