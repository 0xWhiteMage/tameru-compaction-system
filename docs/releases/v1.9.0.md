# Tameru 1.9.0

Prepared 2026-11-11. The engine's code is commit `9f1f1c4`; later commits change documentation only. 1.7.0 and 1.8.0 were never tagged or
published, so this release carries everything since [1.6.0](v1.6.0.md). No Git tag, GitHub Release page or PyPI package exists for it yet: install
the commit (see the README's Quickstart).

## What changed since 1.6.0

- **Structured reports stay whole** (from the 1.7.0 candidate): selected SARIF findings, notebook cells, Kubernetes identity and status, whole Git log entries
  and patches, LCOV records and uncovered lines, JUnit testcases. See the [1.7.0 candidate notes](v1.7.0.md).
- **Safer fail-open**: JSON numbers that reserialisation would change, malformed XML or Unicode and ambiguous structured input return the exact original.
- **Faster credential screen**: a precise `.pgpass` hint replaces the bare `:` literal that sent almost every line to the long credential patterns. A 16x log
  took 5.8 s and now takes 2.9 s with the same answers.
- **Smaller functions, same output**: `compress_context` and `score_blocks` are split into helpers behind a golden-output test
  (`tests/test_golden_compress_context.py`, 216 input and query combinations over 26 option sets).
- **Red-team harness tracked**: `benchmarks/redteam/` (228 adversarial cases). The 1.6.0 run found 5 safety leaks, 4 gold losses and 7 low-savings cases; the 1.9.0
  run ([findings](../../benchmarks/redteam/FINDINGS-1.9.0.md), [notes](../../benchmarks/redteam/NOTES-1.9.0.md)) shows four of the five leaks and all four gold
  losses fixed, and the `atk-superseded` case traced as not a leak (both values are kept with their labels).

## Compatibility

No output change on the comparison corpus relative to 1.6.0. The Hermes plugin 1.9.0 vendors this engine at the same commit; the plugin and the engine are versioned
separately from here on.
