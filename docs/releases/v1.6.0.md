# Tameru v1.6.0 — More tool outputs, more languages

Tameru v1.6.0 adds reducers for a wide range of agent tool outputs, makes generic and empty queries useful instead of returning the original, and extends query handling and the no-query prose brief to many more languages and scripts. A private regex cache keeps long runs from thrashing Python's `re` cache. Retention on the comparison corpus, the 15-case QA battery and the budget sweep is unchanged; three comparison outputs and three battery savings move with the new reducers.

## Highlights

- **Reducers for more tool output.** Linux, macOS and Windows tools (syslog, journal and dmesg, the macOS unified log, `ps aux`, `top`, `vmstat`, `df`, `ping`, `traceroute`/`tracert`, `netstat`, `nmap`, `ipconfig /all`, `systeminfo`, PowerShell tables and error records, msiexec verbose logs, `sysctl -a` and `pg_settings`), containers and Kubernetes (Docker build, `docker ps` and `docker compose ps`, `kubectl get pods`, `top`, `rollout status`, `describe job`), builds and package managers (Terraform/OpenTofu plans, Ansible, CMake, cargo, vite/rollup/webpack/esbuild, pip, npm, yarn, composer, `npm ls`, `npm audit`, `pip freeze`, apt), service logs (nginx, Apache, Redis, PHP, MySQL slow query, HAProxy, klog, web access logs, logfmt), test runners (Gradle, RSpec, PHPUnit, dotnet test, Maven Surefire, quiet pytest, Playwright, jest without a summary, go test) and lint and type checkers (ruff, flake8, pylint, mypy, MSBuild, tsc). Each keeps failures, outliers and summaries and folds the routine rows into a count.
- **Generic and empty queries.** When the query matches little or nearly everything, or is empty, compression anchors on error lines, weak failure lines, isolated warnings, state changes, dashboard summaries and the odd lines of an otherwise uniform log. Large JSON arrays, JSON Lines, CSV/TSV and Markdown tables keep one example, the unusual and matching records and a count line.
- **Multi-language queries and prose.** Query words with Latin diacritics are extracted whole. Question and function words and generic asks (“¿qué pasó?”, “o que aconteceu?”, “résume le rapport”, “ringkasan”) in 20 languages besides English no longer count as query terms. The opt-in `prose_brief` splits long prose into sentences for Latin scripts, CJK, Thai, Devanagari and Arabic, and a sentence repeated back to back folds to one copy with a `[×N]` count in any script.
- **Regex cache.** Query- and input-derived regexes go through a private compiled-pattern cache, with a guard test against `re` cache thrashing. In the internal 174-case replay loop, regex recompiles per loop fell from 156 to 3.
- **Secrets handling.** Env/config dump folding never keeps a secret-looking line on its own and never moves one; the recovery-cache credential screen is unchanged.

## Fixes

- Ratio lines such as `20/40 degraded` and docker `Step N/M` lines are no longer dropped as progress bars.
- A short numeric query term no longer matches inside clock times.
- Output is never longer than the input when no tokens are saved.
- Prometheus `/metrics` output is no longer read as Markdown.
- A query matching a top-level key in multi-document YAML keeps the whole document.

The [CHANGELOG](https://github.com/0xWhiteMage/tameru-compaction-system/blob/main/CHANGELOG.md) lists every change.

## Verification

Measured on this release, Python 3.13.5:

- **Tests:** 1,939 passed, 2 skipped (`python -m pytest -q`); 1,879 passed, 2 skipped with `-m 'not perf'`; the 60 `perf` tests pass. `ruff check .` (ruff 0.15.10) is clean.
- **Release QA battery:** 15/15 passed. Savings are unchanged except the Japanese document (57.5% → 46.8%), the YAML configuration (64.7% → 76.0%) and the large synthetic document (99.5% → 99.9%); every required string is kept and nothing forbidden leaks. The large synthetic document completed in 113.9 ms CPU time against its 1,200 ms gate.
- **Budget sweep:** 15/15 clean at every ratio; mean character savings 77.8%, 69.9%, 61.9%, 41.7% and 24.8% at ratios 0.1, 0.2, 0.3, 0.5 and 0.7.
- **Comparison corpus:** `python benchmarks/compare.py --verify-against benchmarks/comparison-v1.4.1.json` finds the same corpus hash and identical retention (25/25 required strings, 0 forbidden leaks, 16/16 clean). Three outputs change: `jp_musubi` 35.3% → 27.3% saved, `travis_yaml` 64.1% → 76.8%, `pytest_captured_blank_lines` 81.1% → 84.6%. The mean saving is 82.4% (81.9% recorded). Timings are excluded from the check.
- **Packaging:** the wheel builds as `tameru_compaction_system-1.6.0`.

## Comparison record

At release, the competitor comparison was the 2026-10-12 record against Tameru v1.4.1. A fresh comparison of all five runnable methods on Tameru v1.6.0 followed on 2026-11-05 (`benchmarks/comparison-v1.6.0.json`): Tameru 25/25 required strings, 0 forbidden leaks, 16/16 clean, 82.4% mean saved; every competitor's outputs are byte-identical to the v1.4.1 record, and timings were re-measured on a different machine. JEV stays unmeasured. See [current comparisons](https://github.com/0xWhiteMage/tameru-compaction-system/blob/main/benchmarks/COMPARISON.md).

## Publication status

The source and metadata identify 1.6.0. The `v1.6.0` Git tag is published (commit `fa988eb`; its engine code is identical to release commit `386a70c`, the later commits are documentation). No GitHub Release page or PyPI package is published.

## Install

```bash
python -m pip install "git+https://github.com/0xWhiteMage/tameru-compaction-system.git@v1.6.0"
```

Python 3.10+; no runtime dependencies or LLM calls for default extraction. Hermes users must update their separate plugin/vendor copy to receive the engine changes.

## Upgrade notes

- Outputs change for the input shapes the new reducers recognise, and for generic or empty queries that previously returned the original text. Pin 1.5.0 if you need its exact outputs.
- `prose_brief` stays opt-in.

See the repository [README](https://github.com/0xWhiteMage/tameru-compaction-system/blob/main/README.md) for usage, recovery requirements and known limitations.
